# 3D Race Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A blocky 3D view of the race map with themed terrain, box cars and overview / chase / cockpit cameras, beside the existing flat map.

**Architecture:** One new ES module, `map3d.js`, owns a second canvas and a Three.js scene. It reads the app's existing globals (`S`, `carXY`, `order`, `gone`, `opt`, `stations`, `heading`, `blur`, `nearest`) and exposes `window.draw3d()`, which `frame()` calls instead of `draw()` when 3D is on. Pure helpers (heights, noise, ground, theme) sit at the top of the module with `console.assert` self-checks, as `app.js` does.

**Tech Stack:** Vanilla JS, Three.js 0.170.0 and its OrbitControls from jsDelivr through an import map. No build step, no npm.

**Spec:** `docs/superpowers/specs/2026-11-15-race-map-3d-design.md`

## Global Constraints

- No build step, no npm install. New files: `map3d.js` only.
- The 2D map, timing panels and data loading keep their behaviour. `carXY`, `smooth` and `chunk` are not changed.
- No new outside data service. The only new network request is the pinned Three.js from `cdn.jsdelivr.net`.
- Coordinates are in 1/10 m, as in `app.js`. Scene units are metres: scene x = x/10, scene z = -y/10, scene y = height/10.
- Follow `app.js` style: short functions, a one-line comment on the why, `// shortcut:` comments for known limits.
- Deviation from the spec, on purpose: car height is not taken from each car's own `z` (noisy, dropouts). Every car sits on the track's height profile at its nearest station. So `chunk()` stays as it is.

## Review Focus

1. A session whose reference lap has no `z` (live sessions, old data): the world must be flat, not NaN and not empty.
2. WebGL or the CDN unavailable: the 2D / 3D toggle stays hidden and nothing else breaks.
3. Switching race while in 3D, or `S.road` changing from estimated to surveyed: the old world is disposed and rebuilt once, not every frame.
4. The followed car retires or loses signal: the camera returns to overview, it does not freeze or jump to the origin.
5. A circuit name missing from the theme table: grass fallback, no error.

### Task 2: Pure helpers with self-checks

**Files:**
- Modify: `map3d.js` (top of file)

**Interfaces:**
- Produces:
  - `heights(track, c): number[]`: height in 1/10 m for each station in `c` (from `stations(track)`), taken from the nearest `track` point's `z`, blurred with `blur(_, 6)`, shifted so the lowest is 0. All zeros if any `z` is missing or not finite.
  - `rand(seed: string): (ix: number, iy: number) => number`: deterministic value in [0, 1) per integer cell.
  - `noise(r, x, y): number`: smooth value noise in [0, 1) from `r`, bilinear between cells.
  - `THEMES: { [look]: { ground: string[], hill: number, water: number|null, scatter: 'tree'|'cactus'|'rock'|null, city: { min, max, colours: string[], lit: boolean }|null, sky: string } }` with looks `grass`, `forest`, `desert`, `coast`, `city`, `night`.
  - `LOOK: { [circuit_short_name]: look }` covering the current calendar; `theme(circuit) = THEMES[LOOK[circuit] ?? 'grass']`.
  - `CELL = 200` (20 m), `STEP_H = 20` (2 m).
  - `ground(x, y, c, h, th, r): number`: terrain height in 1/10 m at a point. `d` = distance to the nearest station `k`; result = `h[k] - 10 + min(1, d / 3000) * th.hill * (noise(r, x / 2000, y / 2000) - 0.4)`, snapped down to a multiple of `STEP_H`; within `WIDTH` of the station it is `h[k] - 10` unsnapped.

- [ ] **Step 1: Write the failing asserts** at the bottom of `map3d.js`:

```js
{ // a ring with a 10 m hill on one side: heights follow it, lowest is 0; no z at all gives a flat track
  const ring = Array.from({ length: 200 }, (_, i) => ({ x: 3000 * Math.cos(i * Math.PI / 100), y: 3000 * Math.sin(i * Math.PI / 100), z: 500 + 50 * Math.cos(i * Math.PI / 100) }));
  const c = stations(ring), h = heights(ring, c);
  console.assert(h.length === c.length && Math.abs(Math.min(...h)) < 1e-9 && Math.abs(Math.max(...h) - 100) < 5, 'heights');
  console.assert(heights(ring.map(({ x, y }) => ({ x, y })), c).every(v => v === 0), 'heights without z');
  const r = rand('Spa-Francorchamps');
  console.assert(r(3, 7) === rand('Spa-Francorchamps')(3, 7) && r(3, 7) !== rand('Monza')(3, 7) && r(3, 7) >= 0 && r(3, 7) < 1, 'rand');
  const g = (x, y) => ground(x, y, c, h, THEMES.forest, r);
  console.assert(g(c[0][0], c[0][1]) === h[0] - 10 && g(40000, 40000) % STEP_H === 0 && Number.isFinite(g(-99999, 5)), 'ground');
  console.assert(theme('Nowhere') === THEMES.grass && theme('Monte Carlo').city, 'theme');
}
```

- [ ] **Step 2:** Reload the page. Expected: `Assertion failed` / ReferenceError in the console.
- [ ] **Step 3:** Implement the helpers. `rand` hashes the seed string to a 32-bit integer and mixes it with the cell indices (any integer hash).
- [ ] **Step 4:** Reload. Expected: no assertion messages.

### Task 3: Track, terrain, water, scatter and buildings

**Files:**
- Modify: `map3d.js`

**Interfaces:**
- Consumes: Task 2 helpers; `S.road.edges`, `S.track`, `S.box`, `S.circuit`, `S.marks`.
- Produces: `build(): void`, which fills `world`; module state `built` (the `S.road` object the world was built from), `C` (stations), `H` (heights), and `heightAt(x, y): number` (1/10 m, `H[nearest(C, [x, y])]`).

- [ ] **Step 1:** In `draw3d()`: if `!S?.track` render an empty scene; if `S.road?.of !== S.track` do what `draw()` does (`S.road = road(S.track); survey(S);`); if `S.road !== built` dispose every geometry and material under `world`, clear it and call `build()` (Review Focus 3).
- [ ] **Step 2:** Track: one `BufferGeometry` strip, two vertices per station from the left and right edge at `H[i]`, closed. Colour `#2e2e2e`. A white quad across station 0. Sector lines at `S.marks` in a child group whose `visible` follows `opt.sectors` each frame.
- [ ] **Step 3:** Terrain: grid of `CELL` cells over `S.box` grown by 6000 on every side, capped at 250 × 250 cells by enlarging the cell. One `InstancedMesh` of unit boxes scaled to `CELL × (height + 300) × CELL` so no gaps show between steps. Height from `ground()` at the cell centre. Colour picked from `th.ground` by `rand`. Where `th.water !== null` and height < `th.water`, the cell is set to `th.water` and coloured water blue.
- [ ] **Step 4:** Scatter: on land cells more than 400 from the track, with probability 0.08, one instance of the theme's scatter shape (tree = brown box with a green box on top, cactus = tall green box, rock = grey box), each kind as one `InstancedMesh`.
- [ ] **Step 5:** Buildings (`th.city` only): on cells 250 to 1500 from the track, with probability 0.6, a box of height `rand` between `city.min` and `city.max` metres, colour from `city.colours`; when `city.lit`, an emissive window colour and a dark sky. Scatter is skipped on those cells.
- [ ] **Step 6:** Verify in the browser on Spa (forest, big hills), Sakhir (desert), Monte Carlo (city + water), Marina Bay (night), and one circuit not in `LOOK`. Expected: track visible above the terrain everywhere, no terrain poking through the road, no console errors, frame time under 16 ms on this machine.
- [ ] **Step 7:** Commit: `Build the 3D track and themed block terrain`.
